Abstract

Mixture-of-Experts (MoE) models are typically pre-trained with explicit load-balancing constraints to ensure statistically balanced expert routing. Despite this, we observe that even well-trained MoE models exhibit significantly imbalanced routing. This behavior is arguably natural—and even desirable—as imbalanced routing allows models to concentrate domain-specific knowledge within a subset of experts.


Expert parallelism (EP) is designed to scale MoE models by distributing experts across multiple devices, but with a less-discussed assumption of balanced routing. Under extreme imbalance, EP can funnel a disproportionate number of tokens to a small number of experts, leading to compute- and memory-bound failures on overloaded devices during post-training or inference, where explicit load balancing is often inapplicable.


We propose Least-Loaded Expert Parallelism (LLEP), a novel EP algorithm that dynamically reroutes excess tokens and associated expert parameters from overloaded devices to underutilized ones. This ensures that all devices complete their workloads within the minimum collective latency while respecting memory constraints. Across different model scales, LLEP achieves up to 5× speedup and 4× reduction in peak memory usage compared to standard EP, enabling faster and higher-throughput post-training and inference with ~1.9× faster for gpt-oss-120b.

Key Contributions

🔄

Dynamic Load Balancing

LLEP dynamically redistributes tokens and expert weights from overloaded GPUs to underutilized ones at runtime, achieving balanced execution without altering model behavior.

⚡

Significant Speedup

Achieves up to 5× speedup over standard EP under extreme imbalance scenarios, with real-world models like gpt-oss-120b seeing ~1.9× faster throughput.

💾

Memory Efficiency

Reduces peak memory usage by up to 4× compared to standard EP, preventing OOM failures and enabling larger batch sizes on the same hardware.

✓

Exact Computation

Unlike other methods, LLEP is an exact MoE computation algorithm with full backward pass support, preserving model integrity for both training and inference.

Method Overview

✗ Standard EP

Experts are distributed across devices, but imbalanced routing causes some devices (GPU 0) to be overloaded while others remain underutilized (GPU 1).

✓ LLEP (Ours)

Dynamically redistributes excess tokens and corresponding expert weights from overloaded devices to underloaded devices for balanced execution.

💡 Key Insight

When the globally assigned load on an expert group exceeds a capacity threshold, LLEP assigns tokens up to that threshold and transfers the remaining tokens along with the corresponding expert weights to the least-loaded devices. This enables workload sharing while minimizing communication overhead through intelligent cost-aware decisions.

📊 Key Observations

LLEP maintains consistently low memory consumption across all imbalance scenarios, while standard EP's memory usage grows dramatically with imbalance (up to 100GB for Kimi-K2). This enables LLEP to handle larger models with fewer GPUs while preventing OOM crashes under extreme conditions.
